# 生花作品RAW写真のAI一括処理・XMP生成システム

## 1. 開発目的

生花・いけばな作品を撮影したRAW写真について、RAWファイルが入ったディレクトリを指定するだけで、全写真の分類・水平補正・トリミング・レタッチ設定を自動生成し、各RAWと同名のXMPファイルを書き出すPythonシステムを開発してください。

写真の採用・不採用はAIに判断させません。すべての写真を処理し、最後に人間がLightroomクラウド版で分類結果を確認して重複写真を除外します。

各処理を独立したツールとして実装し、オーケストレーターで統合してください。

今回の依頼は構想の提案ではなく、実際にローカルで動作するプログラムの実装です。ただし、画像認識モデルやLightroomとの互換性について、未検証の事項を動作確認済みとして扱わないでください。

## 2. 実行環境と対象画像

- OS：macOS
- ハードウェア：Apple M1またはM2、メモリ24〜32GB
- 言語：Python
- 実行方式：ローカル実行を優先
- RAW形式：まずSony ARWに対応
- 処理枚数：通常は1回100枚未満
- 写真管理：Lightroomクラウド版

対象は展示会場で撮影した生花・いけばな作品です。作品はおおむね画像中央に配置され、花・葉・細い枝・花器を含みます。枝が上下左右に大きく伸びる場合があり、背景には室内の壁・床・建具などが写ります。

**作品の一部を切り落とさないことを優先してください。** 枝先や花器に加え、構図上必要な余白も残します。

## 3. 完成時の操作と入出力

ユーザーはRAWディレクトリを指定して実行します。

```
python -m ikebana_raw process /path/to/photos
```

入力：

```
photos/
├── DSC00001.ARW
├── DSC00002.ARW
└── DSC00003.ARW
```

出力：

```
photos/
├── DSC00001.ARW
├── DSC00001.xmp
├── DSC00002.ARW
├── DSC00002.xmp
├── DSC00003.ARW
└── DSC00003.xmp
```

RAWファイルは変更・移動・削除しません。解析用プレビュー、マスク、JSON、確認用画像、ログは別の作業ディレクトリに保存してください。

## 4. システム構成

以下の8つのコンポーネントに分割してください。

| ID | ツール | 責務 |
| --- | --- | --- |
| T1 | RAW読み込み | RAW列挙、解析用画像生成、撮影メタデータ取得 |
| T2 | 写真分類 | 同じ作品の写真のグループ化、分類タグ生成 |
| T3 | 作品検出 | 花・葉・枝・花器を含む作品全体の領域推定 |
| T4 | 水平推定 | 背景の建築的な直線から補正角度を推定 |
| T5 | トリミング | 回転後の作品全体を残す切り抜き範囲の計算 |
| T6 | レタッチ | 露出・ホワイトバランス・階調・彩度などの補正値生成 |
| T7 | XMP生成 | 分類・回転・トリミング・現像設定をXMPに保存 |
| T8 | オーケストレーター | 実行順序、データ受け渡し、エラー・再実行管理 |

各ツールは独立して呼び出せるようにし、型付きの共通データモデルを通じて結果を受け渡してください。XMPへの書き込みはT7に集約します。

将来、画像認識モデルを変更しても、共通インターフェースを維持すればほかのツールを変更せずに済む設計にしてください。

## 5. 各ツールの詳細仕様

### T1：RAW読み込み

**入力：** ARWファイルのパス

**出力：** 解析用画像、撮影日時、画像サイズ、EXIF Orientation、撮影情報、RAWとプレビュー間の座標変換情報

rawpy/LibRawなどを検討し、解析用プレビューを生成してください。

RAW内の埋め込みJPEGを利用する場合は、元RAWと向き・画角・有効画像領域が一致するか確認してください。解析用画像の座標を、そのままRAWの座標として扱わないでください。

細い枝の検出に必要な解像度を確保しつつ、Apple Siliconのメモリ使用量を抑えてください。

### T2：写真分類

**入力：** 全写真の解析用画像、撮影日時、必要に応じて作品検出結果

**出力：** 各写真のグループID、分類タグ

DINOv2の画像特徴量と撮影日時を組み合わせ、同じ作品を撮影した写真をグループ化してください。

展示会場の背景が似ているため、画像全体の類似度だけで同じ作品と判定しないでください。必要に応じてT3の作品検出結果を利用し、作品領域の特徴量を比較してください。

すべての写真にグループIDを割り当てます。分類が不確実でも、写真を処理対象から除外しません。

XMPには、例えば次の分類タグを書き出します。

```
ikebana
artwork_0001
```

同じ作品の写真に同じグループタグを付け、Lightroomで検索・絞り込みできるようにしてください。

### T3：作品検出

**入力：** 解析用画像

**出力：** 作品領域マスク、作品全体のバウンディングボックス、検出品質、確認用画像

まずは以下の技術構成を検討してください。

- Florence-2：テキスト指示による作品位置の推定
- SAM 2.1：推定位置をもとにした領域抽出
- OpenCV：複数マスクの統合と後処理

検出対象は、花・葉・枝・花器を含む作品全体です。花だけ、花器だけを検出して終わらないでください。

Florence-2に作品全体を指定しても、細い枝や一部の花材が漏れる可能性があります。花器・花・枝などを個別に検出して統合する方法や、SAM 2.1の自動マスク生成も検討してください。

**検出マスクを、そのまま厳密なトリミング境界にしないでください。** 安全余白を追加し、検出が不確実な場合は広い領域を採用してください。

検出できなかった場合は画像全体を保持するフォールバックを返し、後続処理を継続できるようにしてください。

### T4：水平推定

**入力：** 解析用画像、作品領域マスク

**出力：** 回転補正角度、推定品質、基準線情報、確認用画像

OpenCVで背景の壁・床・ドア枠・柱などの直線を検出し、写真の傾きを推定してください。

作品の枝や花器の輪郭を水平推定の基準にしないでください。作品マスクを拡張して除外領域を作り、背景の直線を探します。

Hough変換や線分検出を利用し、複数の基準線から一貫した角度を求めてください。

壁と床の境界が斜めに写っている場合、それは遠近法による可能性があります。単一の線だけで傾きを確定せず、建具などの垂直線も利用してください。

信頼できる基準線がない場合は回転角度を0度とし、その理由を結果に記録してください。

初期実装では、遠近補正ではなく単純な回転補正を対象とします。

### T5：トリミング

**入力：** 作品マスク、作品全体の範囲、水平補正角度、画像サイズ、座標変換情報

**出力：** 最終トリミング範囲、確認用画像

以下の順序で計算してください。

1. 水平補正角度を取得する。
2. 回転後の作品領域を計算する。
3. 花・葉・枝先・花器を含む範囲を求める。
4. 構図上必要な余白を追加する。
5. 回転によって生じる画像外領域を考慮する。
6. 最終的なトリミング範囲を決定する。

すべての写真にトリミング設定を生成します。ただし、全写真を処理することと、全写真を必ず狭く切り抜くことは同義ではありません。

作品が画像端に近い場合や検出に失敗した場合は、作品を切り落とさないよう、元画像に近い広い範囲を採用してください。

回転後の有効画像領域と作品全体を同時に保持できない場合は、その状態を記録してください。作品を切り落としてまで黒い余白を除去しないでください。

### T6：レタッチ

**入力：** 解析用画像、作品マスク、RAWの撮影情報、必要に応じて分類グループ情報

**出力：** RAW現像用の補正パラメータ

以下を対象とします。

- 露出
- ホワイトバランス
- コントラスト
- ハイライト・シャドウ
- 白レベル・黒レベル
- 自然な彩度・彩度

作品領域と背景を区別して画像を解析し、花材本来の色や質感を維持する補正値を生成してください。

白い花の白飛び、暗い枝や葉の不自然な持ち上げ、彩度の過剰な補正を避けてください。

**解析用JPEGの明るさから、Adobe Camera Rawの露出値を単純換算できると仮定しないでください。** RAW現像結果と比較しながら調整できる構成にしてください。

初期実装では、判断根拠が不十分な項目はニュートラルな値を使用してください。

### T7：XMP生成

**入力：** T2〜T6の結果、RAWファイル情報、必要に応じて既存XMP

**出力：** RAWと同名のXMPサイドカーファイル

Adobe Camera Rawの名前空間を使用します。

```
http://ns.adobe.com/camera-raw-settings/1.0/
```

書き出し対象の候補は以下です。

| 内容 | XMP項目 |
| --- | --- |
| トリミング有効化 | crs:HasCrop |
| 回転角度 | crs:CropAngle |
| トリミング範囲 | crs:CropTop、CropLeft、CropBottom、CropRight |
| 露出 | crs:Exposure2012 |
| コントラスト | crs:Contrast2012 |
| ハイライト・シャドウ | crs:Highlights2012、Shadows2012 |
| 白・黒レベル | crs:Whites2012、Blacks2012 |
| ホワイトバランス | crs:WhiteBalance、Temperature、Tint |
| 彩度 | crs:Vibrance、Saturation |

分類タグについては、Lightroomが認識する標準的なXMPキーワード項目を使用してください。dc:subject などの仕様を確認し、実際にLightroomで読み込める形式を採用してください。

XMPの構造・必要な補助項目・回転角度の正負・トリミング座標の定義は、Adobeの仕様とLightroomで作成した実物のXMPを照合して確定してください。

既存XMPがある場合は、無条件に上書きしないでください。既存の編集情報やメタデータを保持する方針を設け、上書きが必要な場合は明示的なオプションを用意してください。

XMPはXMLとして妥当であり、同じ入力で再実行しても不要なタグの重複が発生しないようにしてください。

### T8：オーケストレーター

**入力：** RAWディレクトリ、設定ファイル、実行オプション

**出力：** 全RAWに対応するXMP、処理レポート、確認用画像

以下を担当してください。

- 対象RAWの列挙
- モデルの初期化と再利用
- 各ツールの実行順序の制御
- ツール間のデータ受け渡し
- 写真ごとの処理状況の記録
- エラー発生時の継続処理
- 再実行時の処理済み判定
- XMPの最終書き出し

T2が作品領域を利用する場合は、T3の後に分類を実行してください。

1枚の写真で検出や補正に失敗しても、ほかの写真の処理を止めないでください。失敗した写真についても、可能な範囲でXMPを生成し、失敗内容をレポートに記録してください。

ただし、RAWの読み込み自体に失敗した場合など、正常なXMPを生成できないケースは成功扱いにしないでください。

## 6. 共通データ・座標系

ツール間の入出力には、Pydanticまたはdataclassなどの型付きデータモデルを使用してください。解析結果はJSONにも保存できるようにしてください。

写真ごとに、少なくとも次の情報を管理します。

```json
{
  "photo_id": "DSC00001",
  "raw_path": "/path/to/photos/DSC00001.ARW",
  "preview_path": "/path/to/work/DSC00001/preview.jpg",
  "group_id": "artwork_0001",
  "tags": ["ikebana", "artwork_0001"],
  "artwork_detection": {
    "status": "success",
    "mask_path": "/path/to/work/DSC00001/mask.png"
  },
  "straightening": {
    "status": "success",
    "angle_degrees": 1.2
  },
  "crop": {
    "status": "success",
    "left": 0.05,
    "top": 0.02,
    "right": 0.95,
    "bottom": 0.98
  },
  "develop": {
    "exposure2012": 0.3,
    "contrast2012": 5
  }
}
```

上記の数値はデータ形式の例であり、実際の補正値やXMPの座標定義を示すものではありません。

元RAW・解析用プレビュー・回転後の画像・XMPの座標系を明確に区別してください。

EXIF Orientation、RAWの有効画素領域、プレビューの縮小・回転・クロップを考慮し、座標変換を一元管理してください。

OpenCVで計算した回転角度を、そのまま符号の確認なしに crs:CropAngle へ書き込まないでください。

## 7. 実装・検証方針

最初に、各モデルとライブラリのApple Silicon対応状況を確認してください。特にFlorence-2とSAM 2.1について、使用するバージョン、モデルの取得方法、MPSでの実行可否、CPUフォールバックを明確にしてください。

モデルのAPIや設定ファイル名を推測で記述せず、実際の使用方法を確認して実装してください。

実装後は、各ツールを個別にテストできるようにしてください。画像解析の結果を目視確認できるよう、作品マスク・基準線・回転後の構図・トリミング枠を重ねた確認用画像を出力してください。

XMPについては、まず1枚のARWで次の検証を行ってください。

- LightroomでRAWを開き、回転・トリミング・露出を手動変更する。
- Lightroomが生成した実物のXMPを取得できる方法を確認する。
- 実物のXMPと、Pythonが生成したXMPを比較する。
- RAWと同名のXMPを同じディレクトリに配置し、Lightroomで読み込む。
- 回転・トリミング・レタッチ・分類タグが意図どおり反映されるか確認する。

**新規読み込み時にXMPを認識することと、すでにLightroomクラウド版へ取り込んだ写真へ後からXMPの変更を反映できることは、別々に検証してください。** 既存のクラウド写真に反映できると、未確認の段階で断定しないでください。

## 8. 完成条件

以下を満たす状態を完成とします。

- RAWディレクトリを指定して一括実行できる。
- 対象の全RAWについて分類・作品検出・水平推定・トリミング・レタッチを試行する。
- 写真の採用・不採用を自動判断せず、写真を削除しない。
- 正常に処理できた各RAWについて、同名XMPを生成できる。
- 検出が不確実な写真では、作品を切り落とさない保守的な設定を採用する。
- Lightroomで同じ作品の写真を分類タグから探せる。
- LightroomでXMPの回転・トリミング・レタッチ設定が意図どおり反映される。
- RAWファイルを一切変更しない。
- 処理失敗や確認が必要な写真をレポートで把握できる。
- READMEにインストール方法、モデルの準備、実行方法、設定項目、既知の制約を記載する。

最終的なユーザー体験は「RAWディレクトリを指定して実行 → 全写真のXMPを生成 → Lightroomで分類タグを使って重複写真を除外する」です。

まず、この仕様を実装可能なディレクトリ構成・共通インターフェース・開発順序に落とし込み、その後、各ツールとオーケストレーターを実装してください。
